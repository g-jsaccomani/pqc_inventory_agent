# Phase 4.1.1 — Delegated-Token End-to-End Flow Trace (Before vs. After)

This document traces all 9 stages of the delegated OAuth 2.0 (`access_token`) workflow across `pqc_agent/workspace_server.py`, `pqc_agent/credential_service.py`, `tools/gcloud_bridge.py`, `tools/gcp_inventory.py`, `tools/pqc_detectors.py`, and `main.py`.

## Stage-by-Stage Lifecycle Comparison

| Stage | Component(s) | Behavior Before Phase 4.1.1 (`36dec31`) | Behavior After Phase 4.1.1 |
|---|---|---|---|
| **1. User Auth & Token Acquisition** | `POST /api/auth/google`, `GET /api/auth/oauth/authorize`, `GET /api/auth/oauth/callback`, `POST /api/auth/tool-consent`, `pqc_agent/credential_service.py` | Verified OAuth tokens stored in `pqc_delegated_credentials`, but `store_delegated_token(..., expires_in<=0)` silently fell back to 3600s TTL; malformed tokens with whitespace/control chars were accepted; `/api/auth/tool-consent` (`verify_with_google=True`) did not verify `verified_email == uid`. | Malformed tokens (`ACCESS_TOKEN_INVALID`) and expired tokens (`expires_in <= 0`, `ACCESS_TOKEN_EXPIRED`) fail closed before DB writes; `/api/auth/tool-consent` rejects mismatched Google identities (`403`); `/api/auth/oauth/callback` re-validates scope before binding (`403` on mid-flow revocation). |
| **2. Tenant Identity Establishment** | `activate_request_tenant_user()` (`workspace_server.py`), `set_current_tenant_user()` (`tools/gcloud_bridge.py`) | Verified session cookie / IAP JWT / bearer token binds email identity into `_CURRENT_USER_ID` ContextVar; cross-tenant `user_id` mismatches return `403`. | Preserved unchanged; reinforced on `/api/auth/tool-consent` token verification. |
| **3. Org / Project Scope Binding** | `_default_connection_template()`, `resolve_server_bound_defaults()`, `set_gcp_connection_config()` (`tools/gcloud_bridge.py`) | Non-admin defaults were always `organization_id=""`, `project_id=""` even when `PQC_ALLOWED_PROJECTS` / `PQC_ALLOWED_ORGANIZATIONS` / `PQC_TENANT_SCOPE_POLICY` configured a single scope. Partial policies (`PQC_ALLOWED_PROJECTS` alone) left `has_org_restriction=False`, permitting self-binding of arbitrary orgs. Clients could overwrite or pivot bound org/project via `POST /api/connection` even in production. | `resolve_server_bound_defaults(uid)` auto-binds unambiguous server-authorized org/project on login and connection read. Any configured server policy locks **all three** dimensions (`projects`, `organizations`, `folders`). Production without server policy denies non-admin self-binding (`403 MISSING_AUTHORIZED_SCOPE`). Existing bound non-admin connections cannot be mutated or pivoted via request payloads (`403`). |
| **4. Connection Config Persistence** | `store.upsert_user_connection()`, `get_gcp_connection_config()` (`tools/gcloud_bridge.py`, `pqc_agent/auth_store.py`) | `get_gcp_connection_config()` returned raw DB `organization_id`/`project_id` even if server policy revoked them, and exposed no `active_scope_uri` or `authorized_scope`. | Token & scope checks run **before** `upsert_user_connection()`. `get_gcp_connection_config()` filters reported `organization_id`/`project_id` live against server policy and production rules, returning `active_scope_uri`, `scope_bound_by_server`, and `authorized_scope`. |
| **5. Scan Request Construction** | `POST /api/sessions`, `POST /api/chat`, `GET /api/auth/oauth/authorize`, `PqcOAuth3LOPlugin`, `_resolve_scope()` (`tools/gcp_inventory.py`) | `/api/sessions` fabricated malformed `organizations/` when `organization_id == ""`. `/api/chat` defaulted to hardcoded `organizations/31564119954` and accepted arbitrary client `scope`/`project_id`. `_resolve_scope("default")` silently fell back to `DEFAULT_ORGANIZATION_ID`. `PqcOAuth3LOPlugin` prompted for consent on unauthorized foreign scopes. | `_resolve_and_authorize_request_scope()` resolves omitted scopes to `active_scope_uri` and rejects unauthorized client overrides with `403` before session creation, consent cards, or LLM calls. `_resolve_scope()` resolves symbolic tokens via `_active_tenant_default_scope()` (returning `("UNBOUND", "", "")` for unbound authenticated tenants instead of `DEFAULT_ORGANIZATION_ID`). |
| **6. Inventory Collector Invocation** | `collect_kms_inventory`, `collect_workload_evidence`, `discover_all_crypto_assets`, `compute_pqc_scorecard`, `export_cyclonedx_cbom` (`tools/gcp_inventory.py`), `collect_tls_policies`, `collect_kms_import_jobs` (`tools/pqc_detectors.py`), `main.py` (`run_tools_smoke_test`) | All 5 live collectors called `_get_client_kwargs(scope_uri=scope_uri)` before `_SCAN_CACHE`, but `_fetch_compute_pq_key_exchange()` in `pqc_detectors.py` called bare `_get_client_kwargs()` without a scope. | All 5 live collectors + scorecard + CBOM enforce `_get_client_kwargs(scope_uri=scope_uri)` before cache/SDK. `_fetch_compute_pq_key_exchange()` reuses authorized `client_kwargs` from `collect_tls_policies()` and enforces `scope_uri=f"projects/{project_id}"` if called standalone. Explicit demo scopes (`demo-pqc-project`) and `PQC_SIMULATION_MODE=TRUE` remain supported. |
| **7. `authorize_gcp_scope()` Enforcement** | `authorize_gcp_scope()`, `resolve_authorized_tenant_scope()` (`tools/gcloud_bridge.py`) | Partial server policies did not restrict unmentioned scope types; production without policy trusted DB `conn_org`/`conn_proj`; missing scope produced generic outside-scope message without distinguishing unbound tenants. | Unified `server_policy.has_any_restriction` check closes partial-policy bypass; production without server policy returns empty sets for non-admin users; empty/missing tenant scopes raise `PermissionError("UNAUTHORIZED_RESOURCE_SCOPE (MISSING_AUTHORIZED_SCOPE): ...")` with actionable onboarding instructions. |
| **8. Cloud SDK Client Creation** | `_get_client_kwargs()` (`tools/gcp_inventory.py`), `get_active_gcp_credentials()` (`tools/gcloud_bridge.py`) | Created `oauth2.credentials.Credentials(token=..., quota_project_id=...)` from masked/unmasked connection dict without passing `expiry` or validating token syntax. | Loads directly from `EncryptedDatabaseCredentialService.load_delegated_token()`, enforces expiration & revocation (`ACCESS_TOKEN_REQUIRED`), validates token syntax (`ACCESS_TOKEN_INVALID`), and constructs `oauth2.credentials.Credentials(token=..., expiry=..., quota_project_id=...)`. Zero SDK clients created on any authz/token failure; zero `google.auth.default()` fallback. |
| **9. Authorization Failure Propagation to API/UI** | `workspace_server.py` (`/api/connection`, `/api/chat`, `/api/sessions`, `/api/auth/tool-consent`, `/api/auth/oauth/*`, `PqcOAuth3LOPlugin`), collector JSON error payloads | `/api/connection` returned `403` only on `has_org_restriction`/`has_project_restriction` match; `/api/chat` and `/api/sessions` did not return `403` on unauthorized scopes; `/api/auth/tool-consent` could raise unhandled `500` on invalid token; `after_tool_callback` could re-prompt on permission errors. | `/api/connection`, `/api/chat`, `/api/sessions`, `/api/auth/oauth/authorize`, `/api/auth/oauth/callback`, and `/api/auth/tool-consent` return clean `403` (`UNAUTHORIZED_RESOURCE_SCOPE` / `MISSING_AUTHORIZED_SCOPE`) or `400`/`401` (`ACCESS_TOKEN_INVALID` / `ACCESS_TOKEN_EXPIRED`). Collectors return structured JSON `error` payloads (`UNAUTHORIZED_RESOURCE_SCOPE`, `MISSING_AUTHORIZED_SCOPE`, `ACCESS_TOKEN_REQUIRED`). `PqcOAuth3LOPlugin` returns `SCOPE_AUTHORIZATION_DENIED` and suppresses consent cards on scope/ADC denials. |

## End-to-End Request Flow Diagram (After Phase 4.1.1)

```text
[Client / Browser]
   │
   ├─ 1. Auth (POST /api/auth/google | OAuth 3LO PKCE /authorize -> /callback | POST /api/auth/tool-consent)
   │      ├─ Verify Google credential & email domain (401/403 on failure)
   │      ├─ Verify token syntax & expires_in > 0 (400 on failure)
   │      ├─ Validate target_scope against server policy if active (403 on override/revocation)
   │      └─ Persist envelope-encrypted token (pqc_delegated_credentials) + auto-bind unambiguous server scope
   │
   ├─ 2. Connection / Session / Chat (POST /api/connection | POST /api/sessions | POST /api/chat)
   │      ├─ Reject unauthorized mode='adc' / unapproved impersonation SA (403)
   │      ├─ Reject client scope overrides outside server policy, production self-binding, or re-binding (403)
   │      └─ Default omitted scope to server-bound active_scope_uri (never hardcoded lab org / malformed 'organizations/')
   │
   └─ 3. Live Collection (KMS / Workloads / Crypto Assets / TLS Policies / Import Jobs / Scorecard / CBOM)
          ├─ _resolve_scope(): preserves explicit scopes; resolves symbolic tokens via _active_tenant_default_scope()
          ├─ _get_client_kwargs(scope_uri) [BEFORE _SCAN_CACHE & BEFORE SDK client construction]:
          │      ├─ authorize_gcp_scope(scope_uri): identity + raw/effective ADC + unified server policy + MISSING_AUTHORIZED_SCOPE
          │      └─ get_active_gcp_credentials(): load_delegated_token() (expiry/revocation/AAD) + syntax + oauth2.Credentials(expiry=...)
          ├─ If denied -> structured JSON error (0 SDK clients created, 0 google.auth.default() calls, 0 cached leaks)
          └─ If authorized -> pass client_kwargs to CAI / KMS / Compute SSL Policies clients -> return factual payload
```
